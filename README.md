# popo 朝のニュースブリーフ

毎朝5時に4テーマのニュースを自動で調べ、2人の対話形式の日本語音声（約30分）に仕立てて、
6時前にはiPhoneで聞ける状態にする仕組みです。

- 「きょうの検証」（立てた見立てが、その日の材料でどう動いたか）
- ① 日本の水産（養殖魚 → 天然魚 → その他）
- ② 世界の水産（ぶり類の養殖・消費トレンドを最優先）
- ③ 生成AIの重大ニュース
- ④ AI時代を見据えた世界の教育トレンド
- ＋ 4テーマを横断する「きょうの論点」

海外の情報は日本語に訳して読み上げます。台本と出典URLは、あわせてウェブページに残ります。

---

## 1. 全体の流れ

```
 毎朝5時（GitHubのサーバー上で自動起動）
   ↓
 ① 調べる      Perplexity が6本の調査を回す
                  4テーマ ＋ あなたの注文 ＋ 反証さがし
                  ※ 4テーマの検索には仮説の文章を渡さない（探索を汚さないため）
   ↓
 ② 照らす      集めた材料を事実カードに分け、そこで初めて仮説と突き合わせる
                  確からしさを上下させ、崩壊条件に触れていないか調べる
   ↓
 ③ 台本を書く   Claude が2人の対話形式の日本語台本にする
   ↓
 ④ 読み上げる   Google の音声合成が2つの声で読み上げ、1本のmp3に結合
   ↓
 ⑤ 配信する     RSSを更新（＝Apple Podcastsに自動で降ってくる）
   ↓
 朝6時、iPhoneで再生
```

**パソコンの電源は要りません。** GitHub のサーバー上で走るので、Mac が閉じていても、
電源が落ちていても、旅行中でも毎朝動きます。あなたの環境に依存する部分はひとつもありません。

朝5時にしているのは、日刊水産経済新聞のウェブ更新が毎朝5時だからです。官庁の発表は
早朝には出ず前日のうちに出そろうので制約になりません。米国のAI企業の発表は日本時間の
深夜1〜2時台に集中するため、5時ならすでに入っています。

## 2. 最初に用意するもの

| 用途 | サービス | 費用の目安 |
| --- | --- | --- |
| ニュース調査 | Perplexity API（取得済み） | 月 1,000〜1,500円程度 |
| 台本づくり | Anthropic Claude API（取得済み） | 月 700〜1,000円程度 |
| 読み上げ | Google Cloud Text-to-Speech | 月100万文字まで無料枠。本番でも月30万文字前後の見込み |
| 実行と配信 | GitHub（公開リポジトリ） | 無料 |

費用は台本1日約9,000文字・毎日実行を前提とした概算です。**要確認**：実際の単価は稼働前に各社の
料金ページで確認してください（[Perplexity](https://docs.perplexity.ai/getting-started/pricing) /
[Anthropic](https://platform.claude.com/docs/en/about-claude/pricing) /
[Google TTS](https://cloud.google.com/text-to-speech/pricing)）。

> Google のアカウントを増やしたくない場合は、`config.yaml` の `tts.provider` を
> `openai`（有料・アカウント追加）か `voicevox`（無料・自前で起動）に変えられます。
> 読み上げ部分は差し替え前提の作りにしてあるので、他は何も直さずに切り替わります。

## 3. 設置の手順

### 3-0. 先に手元で動作確認する（5分・費用ゼロ）

GitHub に上げる前に、仕組みが壊れていないかを手元で確かめられます。
APIは1回も呼ばないので、費用はかかりません。鍵も要りません。

```bash
cd ~/Downloads/morning-brief
python3 -m pip install --user PyYAML requests   # 最初の1回だけ
python3 tests/test_daily_run.py
```

**ffmpeg は要りません。** 手元に無ければ、mp3をそのままつなぐ方式に自動で切り替わります
（GitHub のサーバーには入っているので、本番はそちらを使います）。
必要な部品が足りないときは、何をどう入れればいいかを画面が教えます。

**何が起きるか**：フォルダを一時領域に丸ごと複製し、Perplexity・Claude・Googleの3つを
偽物に差し替えて、毎朝の処理を最初から最後まで通します。ダウンロードしたフォルダ自体は
一切変更されません。終わると次のように出ます。

```
[research] 日本の水産 を調査中…
[hyp] 事実カード 2枚を抽出しました
[hyp] 判定: 支持2件 / 反証0件 / 崩壊条件ヒット0件
[hyp] H-001 0.55 → 0.63
[run] 音声を書き出しました: 260825_morningbrief_v1_AI.mp3
通し実行 OK（ffmpeg あり）
...
通し実行 OK（ffmpeg なし）
```

2回走るのは、GitHub のサーバー（ffmpeg あり）と手元の Mac（たいてい無い）の
両方で動くことを確かめるためです。

そのうえで、次の8点を自動で点検します。

1. 調査が6本（4テーマ＋あなたの注文＋反証さがし）走ったか
2. **通常の調査の問いかけに、仮説の文章が混ざっていないか**
3. 反証さがしが崩壊条件だけを狙っているか
4. 仮説台帳が更新され、確からしさが動いたか
5. 台本に検証コーナーが入ったか
6. 注文が使われたあと、受け皿が空に戻ったか
7. 調査の生データが残ったか
8. 音声とRSSができ、RSSが壊れていないか

できあがる音声は、中身が「あー」という電子音の7分間です。文章も音声も偽物なので、
**聞くためのものではありません。配管が全部つながっているかを見るためだけのもの**です。
`通し実行 OK` と出れば、あとは本物の鍵を入れれば本物が出てきます。

ほかに2つあります。

```bash
python3 tests/test_hypotheses.py   # 仮説が偏らない仕掛けが効いているか（8項目）
python3 tests/test_pipeline.py     # 音声の結合とRSS生成だけを確認
```

### 3-1. GitHub のアカウントを作る

**必要です。** https://github.com/signup で無料で作れます。メールアドレスとパスワードだけで、
支払い情報は要りません。

> **Apple Podcasts の話は変わっていません。** GitHubとPodcastsは役割が違います。
> GitHub は「毎朝5時に処理を走らせるサーバー」と「できた音声の置き場」。
> Apple Podcasts は「それを聞く道具」。どちらか一方ではなく、両方使います。
> 自分のパソコンを毎朝5時に起こしておく代わりに、GitHub のサーバーに走らせてもらう、
> という関係です。

### 3-2. 置き場（リポジトリ）を作る

1. 右上の「＋」→「New repository」
2. Repository name: `morning-brief`（何でも構いません）
3. **Public を選ぶ**（Private だと Actions の無料枠と Pages が制限されます）
4. 「Create repository」

中身は公開ニュースの要約なので実害は小さい想定ですが、URLを知らなければ辿り着けないだけで、
技術的には誰でもアクセスできます。秘匿したい内容は入れないでください。

### 3-3. ファイルを上げる（コマンド不要）

git を覚える必要はありません。ブラウザにドラッグするだけです。

**先に隠しフォルダを表示させます。** `.github` という設定フォルダが、Finder では
標準で見えないためです。

1. Finder で `morning-brief` フォルダを開く
2. **`command + shift + .`（ピリオド）** を押す → 薄く `.github` と `.gitignore` が現れる

そのうえで、

3. 作ったリポジトリの画面で「uploading an existing file」（または Add file → Upload files）
4. Finder で `morning-brief` の**中身を全部選び**（`command + A`）、ブラウザの点線枠にドラッグ
5. 下の「Commit changes」を押す

`.github` が一覧に入っていることを確認してください。これが無いと自動実行が始まりません。

### 3-4. 鍵を登録する

**Settings**（リポジトリ上部のタブ）→ 左メニューの **Secrets and variables** → **Actions**。

`Secrets` タブ →「New repository secret」を3回：

| Name | Secret |
| --- | --- |
| `PERPLEXITY_API_KEY` | Perplexity のAPIキー |
| `ANTHROPIC_API_KEY` | Anthropic のAPIキー |
| `GOOGLE_TTS_API_KEY` | いま使っている Google のキー |

一度登録すると二度と表示されません（GitHub 側も読めません）。差し替えは上書きで行います。

`Variables` タブ →「New repository variable」を1回：

| Name | Value |
| --- | --- |
| `BASE_URL` | `https://<あなたのユーザー名>.github.io/morning-brief` |

ユーザー名は全部小文字にしてください。

### 3-5. 公開ページを有効にする

**Settings → Pages** → Source を **GitHub Actions** に変更。

### 3-6. 一度、手で走らせる

**Actions** タブ → 左の「毎朝のブリーフを作る」→ 右の **Run workflow** → 緑の Run workflow。

25〜40分かかります。進行中は各工程の名前が並び、クリックすると手元で見たのと同じログが
流れます。全部に緑のチェックが付けば成功です。

**うまくいかないときの見分け方**

| 止まった場所 | 原因 |
| --- | --- |
| 「番組をつくる」で `PERPLEXITY_API_KEY が設定されていません` | 鍵の名前が違う（大文字小文字も一致させる） |
| 同じ工程で `HTTP 403` | Google のキーの制限、または課金の設定 |
| 「音声を公開する」 | 音声ができていない。ひとつ上の工程のログを見る |
| `deploy` で失敗 | 3-5 の Pages 設定がまだ |

### 3-7. できたものを見る

`https://<ユーザー名>.github.io/morning-brief/` を開きます。反映に数分かかることがあります。
番組ページに、その日の台本・出典・仮説の動きが載っています。

### 3-8. iPhone で登録する

ページに出ている購読URL（`.../feed.xml`）をコピーし、

- **Apple Podcasts**：ライブラリ → 右上の「…」→「URLで番組を追加」
- Overcast / Pocket Casts：「＋」→「URLを追加」

一度登録すれば、翌朝からは自動でダウンロードされます。倍速・スキップ・ロック画面操作は
アプリの機能がそのまま使えます。

### 3-9. あとは放っておく

翌朝5時から自動で走ります。**Mac の電源は入っていなくて構いません。**
旅行中でも、Mac が壊れても、番組は毎朝できます。

## 4. 次回の番組に注文をつける

`requests/next.md` に書いておくと、次の放送がそれを拾います。

```
- ぶりの対米輸出単価が実際に上がっているのか、数量と金額の両方で確かめてほしい
- ペルーの2期漁の枠が決まったかどうか
- 今日は教育を短めに、水産を厚めに
```

書き方は自由です。番組はこれを次の2か所で使います。

1. **調査**：通常の4テーマとは別に、指定分だけの調査を1本追加します。4テーマの問いに混ぜないのは、
   指定に引っぱられて通常の調査範囲が狭まるのを避けるためです
2. **台本**：通常の構成より優先して扱うよう指示します。尺の配分を変える指示にも従います

放送後、書いた内容は `requests/archive/` に日付つきで保管され、`requests/next.md` は空に戻ります。
同じ注文が翌日以降もくり返し使われるのを防ぐためです。

**iPhone から書くには**、GitHub のウェブ版でリポジトリを開き、`requests/next.md` の鉛筆マークを
タップして書き換え、下部の Commit を押します。アプリは不要です。

## 5. 仮説を検証していく仕組み

この番組は「今日は何があったか」を並べるだけでなく、いくつかの**見立て（仮説）**を持ち、
毎朝それが正しいのかを少しずつ確かめていきます。仮説は `hypotheses/ledger.yaml` にあります。
最初の4本はこちらで用意しましたが、書き換え・入れ替えは自由です。

### 初期の仮説に引っぱられないための5つの仕掛け

仮説を持つと、それに合う材料ばかりを集めてしまいます。それを防ぐために、
次の5つを仕組みとして入れてあります。人の意思で気をつけるのではなく、機械が強制します。

| 仕掛け | 中身 |
| --- | --- |
| **探索を仮説で汚さない** | 4テーマの検索に、仮説の文章を一切渡しません。渡すのは「ペルー アンチョビ 漁獲枠 実績」のような、結論を含まない指標クエリだけ。混入すると実行を止めます |
| **見る順番を分ける** | 調べる → 事実カードに分ける → **そこで初めて仮説を見る**。全部を1回でやらせると、要約の時点で仮説に都合よく歪みます |
| **反証専門の係を置く** | 毎朝1本、仮説の崩壊条件だけを狙った検索を回します。「支持する材料は返すな」と明示します |
| **崩壊条件を先に書く** | 「何が起きたらこの見立てを捨てるか」を仮説を立てる時点で2つ書きます。触れたら自動で大きく下がり、その日の番組で必ず扱われます |
| **放置すると下がる** | 支持も反証も出ない仮説は、静かに正しく見えてしまいます。証拠が来ない日は自動で0.5へ戻り、21日で様子見、45日で棚上げになります |

もうひとつ、反証が7日以上出ていない仮説は、**支持証拠の効きを半分にします**。
反証が出ないのは「本当に強い」からか「探し方が偏っている」からかを機械には区別できないので、
安全側に倒しています。

### 番組での扱い

毎朝2本だけ深掘りします（全部に触れると冗長になるため）。選ぶ基準は、確からしさが大きく動いた、
崩壊条件に触れた、反証が出た、しばらく触れていない、など。同じ仮説を連日は扱いません。

台本には「支持する材料と反する材料の両方に必ず触れる」ことを義務づけています。
反証がゼロの日は、それを隠さず言ったうえで「見立てが強いのか、探し方が偏っているのか、
これだけでは分からない」と添えるよう指示しています。ここは省略できません。

### 自分で仮説を足す・入れ替える

`hypotheses/ledger.yaml` に追記します。人が書くのは4つだけです。

- `statement` — 見立て。反証できる形で書く（「〜が増える」ではなく「〜が主因である」）
- `falsifiers` — **崩壊条件を2つ以上**。これが書けない仮説は検証できないので採用しません
- `next_indicators` — 定点で見る指標。**結論を含む語を入れない**（×「信頼性で選ばれている ぶり 米国」／○「ぶり 輸出 数量 米国 月次」）
- `decision_link` — この見立てが、実務のどの判断に効くか

`confidence` や `status` は仕組みが管理するので、手で触らなくて構いません。

```bash
python tests/test_hypotheses.py   # 上の5つの仕掛けが効いているかの確認
```

## 6. ためたデータを掘り返す

毎朝、次の3つが `data/` に残ります。台本は要約なので、掘り返すときはこちらが役に立ちます。

| ファイル | 中身 |
| --- | --- |
| `data/YYMMDD_research.json` | 調査の生の結果と出典。抽出をやり直したくなったとき用 |
| `data/YYMMDD_facts.json` | その日抜き出した事実（内容・時点・確度・出典URL） |
| `data/facts.csv` | 全期間の事実を1本に積んだもの。Numbers でそのまま開けます |

1年ためても全部で25MB程度なので、GitHub に置いたままで問題ありません（音声だけは別置きにしてあります）。

**掘り返し方**：Claude のデスクトップアプリで、このフォルダを連携して聞くのが一番早いです。
新しく作るものはありません。

> 今年のぶり輸出の話を全部出して。数値は出典と日付つきで表にして

`facts.csv` を Numbers で開いて自分で眺めるのも有効です。

## 7. あとから変えたくなったら

**触るのは基本 `config.yaml` だけ**です。

| やりたいこと | 直す場所 |
| --- | --- |
| テーマを足す・減らす・書き換える | `segments:` |
| コーナーの長さを変える | 各コーナーの `minutes:` |
| 声を変える | `hosts:` の `google_voice` |
| 話す速さを変える | `tts.speaking_rate`（1.0が標準） |
| 読み上げサービスを変える | `tts.provider` を `google` / `openai` / `voicevox` |
| 台本の質を上げる | `script.model` を `claude-opus-5` に |
| 調査を深くする | `research.preset` を `high` に |
| 配信時刻を変える | `.github/workflows/daily.yml` の `cron`（UTC表記。日本時間−9時間） |
| 検証コーナーの長さ | `hypothesis.broadcast.minutes` |
| 仮説の検証をやめる | `hypothesis.enabled` を `false` に |

## 8. 手元で試すとき

```bash
pip install -r requirements.txt
cp .env.example .env      # 鍵を書き込む
set -a && source .env && set +a

python src/run.py --dry-run                     # 調査と台本だけ（音声を作らないので安い）
python src/run.py                               # 通し
python src/run.py --script-only out/xxx_script.json   # 台本から音声だけ作り直す
python tests/test_pipeline.py                   # 鍵なしで配管の確認
python tests/test_hypotheses.py                 # 仮説まわりの確認
python tests/test_daily_run.py                  # 毎朝の流れを丸ごと通す（APIは呼ばない）
```

同じ日に作り直しても上書きはされません。`260824_morningbrief_v1_AI.mp3` の次は `_v2_AI.mp3` になります。

## 9. 承知しておくべき点

- **公開範囲**：GitHub Pages は公開URLです。URLを知らなければ辿り着けませんが、
  技術的には誰でもアクセスできます。中身は公開ニュースの要約なので実害は小さい想定ですが、
  秘匿したい内容は入れないでください。
- **起動時刻のずれ**：GitHub の定時実行は混雑時に数十分遅れることがあります。
  4時起動・6時到着なら余裕がありますが、遅延自体は避けられません。
- **内容の正確さ**：台本は「調査結果の外に出ない」よう指示していますが、要約や翻訳の過程での
  取り違えは起こりえます。仕事で使う数字は、必ずページ下部の出典で裏を取ってください。
- **費用の見張り**：各社の管理画面で使用量アラートを設定しておくことを勧めます。

## 10. まだ入っていないもの

**音声で対話する機能**（「その話もう少し詳しく」と話しかけて掘り下げる）は、この版には入っていません。
仕組みとしては、その日の台本と出典をそのまま材料にして、ブラウザ上で音声のやり取りをする形になります。
必要になったら、この土台の上に足せます。
